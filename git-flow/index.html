Git Rebase Workflow Tool

Nhập branch cá nhân — tự động tạo lệnh git theo từng tình huống.

Trường hợp 1: Bạn đang có thay đổi chưa commit và muốn lấy code mới nhất từ main.
1 Lưu tạm thay đổi
git stash
2 Chuyển sang main và lấy code mới nhất
git checkout main git pull origin main
3 Quay lại branch đang làm
git checkout feat/user-management
4 Rebase lên main mới nhất
git rebase main
5 Khôi phục code đã stash
git stash pop
Trường hợp 2: Bạn đã commit xong và muốn rebase với main mới nhất.
1 Lấy code mới nhất từ main
git checkout main git pull origin main
2 Quay lại branch cá nhân
git checkout feat/user-management
3 Rebase
git rebase main
Git báo CONFLICT (content): Merge conflict in xxx.cs — xử lý theo các bước sau.
1 Kiểm tra file bị conflict
git status
2 Sau khi sửa xong conflict trong file
git add . git rebase --continue
Nếu còn conflict, Git sẽ tiếp tục báo — lặp lại bước 2 cho đến khi xong.
Muốn hủy rebase?
git rebase --abort

Branch sẽ quay về trạng thái trước khi rebase.

Đảm bảo branch đã rebase với main mới nhất trước khi tạo PR.
1 Cập nhật main và rebase
git checkout main git pull origin main git checkout feat/user-management git rebase main
Push lên remote
Lần đầu Chưa có branch trên remote
git push -u origin feat/user-management
Sau rebase Branch đã tồn tại trên remote
git push --force-with-lease
Không dùng git push --force — có thể ghi đè thay đổi của người khác.
Toàn bộ flow từ lúc đang code đến khi tạo PR.
